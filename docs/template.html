只统计单品——套餐与多人份拼盘份量口径不同，混排没有可比性。

这个求解器较真的地方

  • 套餐真的拆开算。调用 query-meal-detail 把「巨无霸三件套」还原为汉堡 + 薯条 + 可乐后逐项累加营养。整份套餐按单品计会让热量偏差一倍以上。
  • 拒绝估算。营养数据缺失的商品一律标注并排除，不使用模糊匹配或近似值兜底——宁可少推荐，也不给你一个看起来有数但其实是编的组合。
  • 主食约束。一顿正餐至少得有一件咸食主食，否则「最省型」会理直气壮地给你推荐「新地 + 冰淇淋」。
  • 全枚举而非贪心。菜单规模有限，直接枚举 1~3 件的全部组合取全局最优，不是近似解。
