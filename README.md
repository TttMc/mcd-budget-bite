# 麦麦预算餐盘 · mcd-budget-bite

> 给我一个预算，还你一份「吃得饱、花得值、热量心里有数」的麦当劳组合。

基于 [麦当劳中国 MCP](https://github.com/M-China/mcd-mcp-server) 开发的点餐决策 Skill。
在**预算上限**与**热量上限**双重约束下枚举全部可行组合，输出三套方案、热量贴士与性价比天梯榜。

**[👉 在线 Demo · 拖动滑块直接玩](https://tttmc.github.io/mcd-budget-bite/)** ｜ [离线单文件版](./docs/index.html)（下载后双击打开，不联网也能用）

## 先玩一下

`docs/index.html` 是一个**零依赖单文件页面**——全部数据内联，不需要起服务、不需要 Token、不联网、不下单。

## 为什么是它

麦当劳的点餐决策通常只有两个流派：

- **省钱派**：找券、凑满减、算折扣 —— 但不告诉你这顿多少大卡
- **热量派**：算热量、配宏量 —— 但不告诉你这顿要花多少钱

现实是，**预算和热量往往是同时存在的约束**。你说「今天午饭只有 30 块」，和「我在减脂，这顿别超 700 大卡」，通常是同一个人、同一顿饭。

麦麦预算餐盘把这两条约束放进同一个求解器，一次性给出答案。

## 它和其他点餐 Skill 有什么不同

| | 常见做法 | 麦麦预算餐盘 |
|---|---|---|
| 目标 | 单目标：最便宜 或 热量最低 | **双约束**：预算 × 热量同时成立 |
| 输出 | 一个「最优解」 | **三套方案**：最饱 / 最省 / 最均衡，决定权还给你 |
| 度量 | 无 | **性价比天梯榜**：每元热量、每元蛋白质 |
| 套餐 | 大多只算单品 | 拆解套餐子项累加营养 |
| 缺失数据 | 估算或用近似值 | **标注缺失并排除，绝不猜测** |

## 快速开始（命令行）

### 1. 申请 MCP Token

访问 [https://open.mcd.cn/mcp](https://open.mcd.cn/mcp) → 登录（手机号验证）→ 控制台 → 激活 → 复制 Token。

### 2. 配置 MCP

复制 `mcp-config.example.json`，把 `YOUR_MCP_TOKEN` 换成真实 Token。
在 WorkBuddy 中：左侧边栏【专家·技能·连接器】→【连接器】→【自定义连接器】→【配置MCP】。

### 3. 运行

```bash
git clone https://github.com/<你的账号>/mcd-budget-bite.git
cd mcd-budget-bite
export MCD_MCP_TOKEN=<你的 token>

# 预算 30 元、热量上限 800 大卡
python scripts/solve.py --store 1450104 --budget 30 --kcal 800

# 完全离线复算（用仓库自带的缓存数据，不联网、不需要 Token）
python scripts/solve.py --budget 30 --kcal 800 --offline
```

零第三方依赖，Python 3.9+ 即可。

> 完整使用说明（含 WorkBuddy 对话用法、换门店、场景配方、常见问题）
> 见 [使用教程.md](./使用教程.md)。

不知道自己所在城市的门店编码？

```bash
python scripts/find_store.py 北京市 王府井
```

### 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--store` | `1450104` | 门店编码，用 `query-nearby-stores` 获取 |
| `--budget` | `30` | 预算上限（元） |
| `--kcal` | `800` | 热量上限（kcal） |
| `--max-items` | `3` | 组合最多件数 |
| `--no-combos` | 关 | 排除套餐，只组合单品 |
| `--offline` | 关 | 只用 `data/` 缓存，不联网 |

## 设计取舍

**为什么用全枚举而不是贪心/动态规划？**
单店在售餐品约 121 项，限制在 1～3 件组合，搜索空间只有十万量级，全枚举几秒内跑完且**保证全局最优**。用近似算法反而引入了不可解释性。

**为什么不做模糊匹配营养数据？**
实测过。`巨无霸三件套` 会被模糊匹配到 `巨无霸`，但三件套还含薯条和可乐，热量差一倍以上。
**「看起来匹配上了其实错了」比「匹配不上」危险得多。** 所以本项目只做严格匹配，
匹配不上一律标注缺失并排除。当前 121 项中约 55 项可精确计算，其余为限定新品或规格歧义项。

**为什么天梯榜只统计单品？**
套餐和多人份拼盘（如十翅拼盘）的份量口径不同，混排没有可比性。

**为什么限制一顿必须含主食？**
不加这条约束，「最省型」会给你「新地 + 圆筒冰淇淋」——确实便宜，但不是一顿饭。

## 目录结构

```
mcd-budget-bite/
├── SKILL.md                     # Skill 定义（触发条件与工作流）
├── README.md                    # 项目介绍
├── 使用教程.md                   # 完整使用说明
├── MCP_INTEGRATION.md           # MCP 接入说明
├── CONTEST_DECLARATION.md       # 参赛声明（官方模板，未改动）
├── mcp-config.example.json      # 脱敏配置示例
├── workbuddy.md                 # WorkBuddy 开发上下文
├── docs/
│   ├── index.html               # 在线 Demo 单文件页（数据内联，双击即用）
│   ├── template.html            # Demo 模板（含占位符，供 build_demo 注入）
│   └── demo_data.json           # Demo 用的候选集快照
├── scripts/
│   ├── mcp_client.py            # MCP Streamable HTTP 客户端（零依赖）
│   ├── solve.py                 # 双约束求解器
│   ├── find_store.py            # 门店编码查询
│   ├── export_demo_data.py      # 导出候选集 → docs/demo_data.json
│   ├── build_demo.py            # 把数据注入模板 → docs/index.html
│   ├── verify_demo.js           # 前端与求解器的一致性对拍（Node 运行）
│   └── .env                     # Token（已在 .gitignore 中，不提交）
└── data/
    ├── raw_meals_<门店编码>.json      # 菜单缓存（按门店隔离）
    ├── meal_details_<门店编码>.json   # 套餐拆解缓存（按门店隔离）
    └── raw_nutrition.json             # 营养数据缓存（全国通用）
```

> **为什么缓存要按门店拆文件？**
> 菜单价格和套餐结构都是门店维度的（例如麦香鸡上海 ¥17 / 北京 ¥16.5）。
> 早期版本共用单个缓存文件，查过 A 店后再查 B 店会**静默读到 A 的数据**——
> 价格差只有几毛到 1 元，极难察觉。现在每个门店独立文件，且缓存里写入了
> 来源门店标记，离线读取时会校验，不一致直接报错而不是给出错误答案。
